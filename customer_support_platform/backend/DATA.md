# Data card — knowledge base

The AI assistant's knowledge base is built from public Kaggle datasets, transformed
into support documents by `scripts/build_kb.py`. Raw downloads live in
`backend/data/kaggle/` (git-ignored); the build script is the source of truth.

## Sources

| Dataset | Rows used | License | Role in the KB |
|---|---|---|---|
| [Bitext – Gen AI Chatbot Customer Support](https://www.kaggle.com/datasets/bitext/bitext-gen-ai-chatbot-customer-support-dataset) | 26,872 → 11 docs | **CDLA‑Sharing‑1.0** | One support guide per category (Orders, Refunds, Payments, Account, Delivery, …). For each intent, the most informative canonical answer is kept and `{{placeholders}}` are normalized. |
| [E‑commerce FAQ Chatbot Dataset](https://www.kaggle.com/datasets/saadmakhdoom/ecommerce-faq-chatbot-dataset) | 79 → 6 docs | Kaggle "Data files © Original Authors" (non‑commercial coursework use) | Q&A pairs bundled into 6 topical FAQ documents. |
| [Synthetic IT‑Related Knowledge Items](https://www.kaggle.com/datasets/dkhundley/synthetic-it-related-knowledge-items) | 100 → 98 docs | CC0‑1.0 (public domain) | IT‑helpdesk articles (VPN, email setup, password/PIN resets, printers, …), one document per topic. `alt_ki_text` / `bad_ki_text` columns are unused. |
| [Sample RAG Knowledge Item Dataset](https://www.kaggle.com/datasets/dkhundley/sample-rag-knowledge-item-dataset) | 10 | CC0‑1.0 | **Not ingested** (topics overlap the IT set). Used as a retrieval eval set → `tests/data/rag_eval.jsonl`. |

Total: **~115 documents**, embedded with `BAAI/bge-small-en-v1.5` (fastembed, local, 384‑dim).

## Rebuild

```bash
# 1. get a Kaggle API token: kaggle.com → Settings → "Create New Token"
#    then set it (KGAT_… value):
export KAGGLE_API_TOKEN=<your token>

# 2. download the datasets
cd backend && mkdir -p data/kaggle
for ds in \
  bitext/bitext-gen-ai-chatbot-customer-support-dataset \
  saadmakhdoom/ecommerce-faq-chatbot-dataset \
  dkhundley/synthetic-it-related-knowledge-items \
  dkhundley/sample-rag-knowledge-item-dataset ; do
    kaggle datasets download -d "$ds" -p "data/kaggle/$(basename $ds)" --unzip
done

# 3. build + embed the knowledge base
python -m scripts.build_kb          # or:  python -m app.seed --fresh --kaggle
```

Without Kaggle access, `python -m app.seed --fresh` falls back to 4 hand‑written
sample documents.

## How it's used (RAG)

On every customer message (`app/api/messages.py`):

1. `knowledge_service.retrieve_context()` embeds the message with the same
   model and runs cosine similarity over all active chunks.
2. Chunks scoring ≥ `RAG_MIN_SCORE` (0.5) become a numbered context block; the
   top `RAG_TOP_K` (4) are kept.
3. The block is prepended to the system prompt and sent to the configured
   provider (`AI_PROVIDER`: `mock` by default, or `gemini` / `groq` / …).
4. The answer plus its citations (`{document_id, title, score, snippet}`) are
   saved on the AI message (`Message.sources`) and returned by the API, so the
   dashboard and mobile app can show "based on: …".
5. If retrieval finds nothing above the floor, the model answers un-grounded and
   is told to say it isn't certain and offer a human agent.

`tests/data/rag_eval.jsonl` (10 held-out Q&A from the Sample RAG KI set) drives a
recall@5 check in `tests/test_rag_retrieval.py`.

## Notes

- Bitext content is synthetic (LLM‑generated by Bitext), not real customer data — no PII.
- The IT and e‑commerce domains are intentionally mixed so retrieval has to discriminate
  between topics during the demo. (Side effect: "reset my password" pulls the IT
  password-reset articles. Archive those docs from the KB admin screen for a
  purely e‑commerce demo.)
- Attribution for CDLA‑Sharing‑1.0 (Bitext) is required and satisfied by this file.
